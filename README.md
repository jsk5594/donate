# 기부 플로우: 투명한 기부, 따뜻한 세상 (Next.js)

들어온 돈 = 나간 돈(수혜자에게 간 돈·운영비·모금에 쓴 돈) + 남은 돈. 회계 용어로는 기부받은 돈(차변) = 사업수행비용·일반관리비용·모금비용 + 미집행 잔액(대변)입니다.
모든 모집건을 **대차대조표 형식**으로 공개하고, 운영 세칙(기부금품법 등 국내 법령 + 해외 기준)으로 자동 판정하며, AI가 지출 내용과 모집기관 이력을 검토하는 서비스입니다.

- 접속 주소: http://localhost:3000 (별도 서버 배포 없이 PC에서 로컬 실행. 아래 [실행](#실행) 참고)
- 화면에는 서비스 문구만 두고, 시연·데이터에 관한 설명은 이 문서의 [시연 및 데이터 안내](#시연-및-데이터-안내)에 모았습니다.

## 주요 기능

1. **대차대조표·투명도 점수**: 모집건마다 '기부받은 돈 = 쓰인 돈 + 남은 돈'을 공개하고, 운영 세칙 7개 기준(법정 모금비용 한도 등)으로 자동 판정해 0~100점으로 표시
2. **AI 모집 목적 점검**: 모집 목적과 지출 내용의 의미를 대조해 확인이 필요한 지출과 기관에 물어볼 질문 제시
3. **AI 지출 패턴 점검**: 분할 결제·증빙번호 중복 등 8가지 기준으로 고르고 확인이 필요한 이유 설명
4. **AI 기관 살펴보기**: 5년 결산 공시·외부감사·처분 이력으로 신뢰 등급과 점검 의견 제시
5. **AI 결산 보고서**: 원장과 금액·비율을 대조 검증한 뒤 자동 게시
6. **기부 도우미(챗봇)·기부내역 조회**: 가명처리된 원장과 운영 세칙·법령 원문(RAG)을 근거로 답변, 기부코드로 내 기부금 사용처 조회
7. **재난 피해지 긴급 모금 지도**: 재난 모집건을 단계별로 지도에 표시하고 기부 참여 창구로 연결

## 실행

```bash
git clone [공공GitLab 프로젝트 주소]   # 내려받은 폴더로 이동
npm install
npm run build && npm start   # 브라우저에서 http://localhost:3000 접속
npm run dev                  # (개발 모드)
```

Node 22.13+ 필요(내장 `node:sqlite` 사용). DB·외부 서비스 없이 바로 실행되며, AI·뉴스 API 키가 없어도 모든 화면이 작동합니다(AI 결과는 '자동 분석'으로 표시). AI를 연결하려면 `.env.example`을 `.env.local`로 복사해 키를 넣습니다([AI 연결](#ai-연결) 참고).

```bash
npm run db:seed    # 5개년 데이터를 data/donation-flow.db(SQLite)로 다시 생성
npm run rules:sync # 운영 세칙 근거 법령·자료를 점검하고 법령 원문 갱신
```

앱은 이 DB 파일을 읽기 전용으로 열고, 파일이 없으면 생성기(`mock-data.ts`)로 대체합니다.

## 화면 용어

처음 온 기부자도 읽을 수 있게 화면에는 쉬운 말을 쓰고, 점선 밑줄에 마우스를 올리면 원래 용어를 보여 줍니다(`src/lib/terms.ts`). 운영 세칙 본문과 결산 보고서 본문은 공식 문서라 원래 용어를 그대로 씁니다. AI가 쓰는 글에도 같은 기준을 적용합니다(`client.ts`의 `PLAIN_STYLE`).

| 화면 표기 | 원래 용어 |
|---|---|
| 수혜자에게 간 돈 | 사업수행비용 |
| 운영비 | 일반관리비용 |
| 모금에 쓴 돈 | 모금비용 |
| 남은 돈 | 미집행 잔액 |
| 들어온 돈 / 나간 돈 + 남은 돈 | 대차대조표 차변 / 대변 |
| 장부 일치 | 정합성 |
| 쓴 돈 중 수혜자에게 간 비율 | 사업수행비용 비중(총지출 대비) |
| 투명도 점수 | 기부투명도지수 |
| 지출 항목 | 통계목 |
| 사용 내역 공개 | 공개주기·결과 보고 |
| 통과 / 주의 / 기준 초과 | 판정 등급 양호 / 주의 / 위반(내부 값) |

## AI 연결

`.env.local`(깃 제외, 양식은 `.env.example`)에 키를 넣고 서버를 다시 시작하면 5개 AI 기능이 실제 모델로 동작합니다.

- `OPENAI_API_KEY` / `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` 중 하나 이상, 필요하면 `*_MODEL`
- `AI_PROVIDER`로 제공자 고정(비우면 키가 있는 첫 제공자). `OPENAI_BASE_URL`로 Ollama·vLLM 등 OpenAI 호환 서버(Gemma·GPT-OSS·EXAONE 등) 연결 가능. 키가 필요 없는 서버도 `OPENAI_API_KEY`에는 아무 값이나 넣어야 합니다.
- OpenRouter 사용 예: `AI_PROVIDER=openai`, `OPENAI_BASE_URL=https://openrouter.ai/api/v1`, `OPENAI_MODEL=anthropic/claude-sonnet-5.5`, `OPENAI_API_KEY=sk-or-...`. 추론을 끌 수 없는 모델이 있어 OpenRouter 주소일 때는 추론을 짧게(low) 요청하고 답변 토큰 여유를 더 줍니다. 화면 배지는 `OpenRouter · 모델명`으로 표시됩니다.
- 키가 없으면 같은 원장 지표와 판정 기준으로 규칙 기반 결과를 만들고, 화면 배지에 **'자동 분석'**으로 표시합니다. 키가 있으면 배지에 `AI · 모델명`이 표시됩니다.
- 신뢰 장치: AI에는 원장에서 조회한 데이터만 전달 · 응답은 JSON 형식 검증 · 결산 보고서는 본문 금액·비율을 원장과 대조해 불일치 시 게시하지 않음 · 모든 AI 호출에 공통 문체 기준(짧은 문장, 줄표·상투어 금지)을 붙임(`client.ts`의 `PLAIN_STYLE`)

## 뉴스 연결

메인 페이지 '최신 기부 뉴스' 카드는 [네이버 뉴스 검색 API](https://developers.naver.com/apps)를 씁니다. `.env.local`의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 넣으면 최신 기사 3건을 보여 주고, 누르면 언론사 원문으로 이동합니다. **키가 없으면 미리 만든 기사 3건을 보여 주고, 카드 제목과 기사 화면에 '가상 뉴스' 표시를 붙입니다**(화면에서 가상임을 밝히는 유일한 곳). 실제 보도처럼 보이지 않게 하기 위함입니다. 응답은 서버 메모리에 30분 보관합니다.

## 시연 및 데이터 안내

화면에는 테스트·시연 문구를 두지 않았습니다. 아래 사항은 심사·시연 때 참고하세요.

### 데이터

- **모든 데이터는 가상입니다.** 모집건 52개(2022~2026년), 기부 12,040건, 지출 2,182건, 주관기관 8곳의 5년 이력은 시드가 고정된 생성기로 만들었으며 실제 기관·인물과 관계가 없습니다. 개인정보는 없습니다.
- 모집기관·거래처 이름은 실존 기관과 겹치지 않도록 지은 가상의 이름입니다. 고향사랑 모집건의 군(하동군·영양군 등)과 지역명은 실제 지명을 쓰지만 금액·판정은 가상입니다.
- 지역 표기: 2026. 7. 1. 출범한 전남광주통합특별시를 '전남광주'로 표기합니다. 통합 전에 끝난 모집건은 당시 지명(전남·광주)을 두고, 지도·통계에서는 전남광주로 묶어 셉니다.

### AI 점검 검증 사례

모집 목적 점검과 지출 패턴 점검이 실제로 찾아내는지 확인할 수 있도록 데이터에 정답 사례를 넣었습니다(`src/lib/audit-plants.ts`, 조회는 `getAuditTruth()`, 난수를 쓰지 않아 기존 데이터와 비용 유형별 합계가 그대로입니다).

- **목적 외 사용 10건**: 이사회 송년 만찬, 사무국 업무용 차량 리스료(운영비를 사업비로 분류), 후원의 밤 가수 출연료(모금비용을 사업비로 분류) 등. 그중 2건(숲 복원 모집건의 '어린이 영어캠프 교재 구매', 장애아동 보조기기 모집건의 '지역 축제 불꽃놀이 연출')은 점검 키워드가 없어 **AI의 의미 대조로만** 찾을 수 있습니다.
- **헷갈리지만 정상인 대조군 4건**: 복구 자원봉사자 식비, 어업인 안전교육 강사료, 방한 내복 대량 구매, 창호 단열 공사. 잘못 잡으면 오탐입니다.
- **이상 거래 6건**: 분할 결제, 증빙번호 중복, 동일 금액 반복 지급, 정액 반복 지급, 심야 처리 2건.
- AI 키 없이(자동 분석) 측정한 결과: 목적 외 사용 10건 중 8건 탐지(AI 전용 2건 제외 전부), 대조군 오탐 0건, 이상 거래 6건 중 6건 탐지, 정답 밖 신호 0건. 측정 함수는 `scanPurpose()`·`scanAnomalies()`의 `validation`입니다.

## DB로 교체하기

1. `src/lib/types.ts`의 `DonationRecord`, `ExpenseRecord`, `Campaign`, `Category` 구조로 테이블을 설계합니다.
2. `src/lib/repository.ts`에 `DbRepository implements Repository`를 추가하고 `getRepository()`에서 반환합니다.
3. **가명처리는 반드시 저장소 계층에서** `toPublicDonation` / `toPublicExpense`를 거쳐 내보냅니다. 원본 이름·연락처는 API 응답과 React 컴포넌트에 전달되지 않습니다.
4. 전광판은 `getLiveDonations()`를 "최근 N건 DESC" 쿼리로 바꾸면 됩니다.

## 운영 세칙 근거 법령 점검

법령이 바뀌면 세칙 근거도 따라 바뀌어야 하므로, `npm run rules:sync`(`scripts/sync-rules.mjs`)로 근거 법령과 자료를 다시 확인합니다. 인터넷 연결이 필요하며, 실행하지 않아도 저장소에 들어 있는 조문(`data/law-articles.json`)으로 화면이 작동합니다.

1. **법령 원문 반영**: 기부금품법·같은 법 시행령·재해구호법·고향사랑기부금법의 현행 조문을 가져와 `data/law-articles.json`을 새로 씁니다. 조문 단위로 이전 것과 비교해 바뀐 조문 번호를 기록합니다. 세칙 상세의 '관련 법령 원문'과 기부 도우미(RAG)가 이 파일을 읽으므로, 서버를 다시 시작하면 새 조문이 쓰입니다.
2. **근거 자료 변경 감지**: 각 장의 '근거 자료' 링크(1365기부포털, 법제처 해석 등)를 열어 본문 지문을 비교합니다.
3. **세칙 본문은 사람이 검토**: 판정 비율 같은 세칙 본문은 해석이 들어가므로 자동으로 고치지 않습니다. 변경이 있으면 해당 장에 '근거 법령이 바뀌었습니다 · 세칙 검토 중'이 뜹니다. 검토 후 `data/rules-sync.json`의 해당 항목 `reviewed`를 `true`로 바꾸면 안내가 사라집니다.

(선택) 저장소를 GitHub에 올리면 `.github/workflows/sync-rules.yml`이 매월 1일 같은 점검을 자동으로 실행합니다. GitLab에서는 동작하지 않으며, 로컬 실행에는 필요 없습니다.
